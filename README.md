# BeltVision

BeltVision 是运行在工控机上的多皮带机视觉监测系统：识别皮带文字，保存每轮测量的频率、结果和证据图片，供之后按文字查找、查看和人工复核。一台工控机管理多台机器，每台机器绑定相机、DI 输入通道和频率仪。

## 一轮测量怎么完成

启动监测后，系统读取配置和已启用机器，连接海康相机并加载共享 OCR 模型，再监听现场 Modbus DI。

1. 现场 **START**：DI 从关闭变为开启，为本机创建一轮测量，同时开始相机采集和频率监听。
2. 相机默认采集 **1 秒**，随后筛帧并进行 OCR；频率监听继续等待现场结束。多机共用一个 OCR 实例，排队等待与实际识别分别计时。
3. 现场 **STOP**：DI 从开启变为关闭（代码中称 `CLOSE`），停止本轮采集，冻结关闭信号前最后一条有效频率。相机真正停流后解除现场占用，下一根皮带可立即 START；本轮 OCR、证据保存和入库继续后台处理。
4. STOP 与 OCR 结果都到齐后，先保存 JPG 证据，再写入 SQLite 测量记录；各轮按自己的 `session_id` 独立结算一次。完成回调在本轮离开现场、业务终结、实际线程及任务结束、帧载荷消费或丢弃后回收上下文并归还容量。

启动和 IO 重连后的首份 DI 只建立基线，不补发启停事件；若现场仍开启，先等待真实关闭。IO 中断会结束尚未关闭的周期，已关闭且正在识别或保存的周期继续处理。

## 重要业务约定

### 文字与查询

正式 OCR 文字统一转大写、删除所有空白，按 **20 / 8 / 3 / 2 位**排列，可靠候选最低置信度为 **0.8**：

- 20 位不限格式；3、2 位必须为纯数字，各取置信度最高的一条。
- 8 位必须为“7 位数字 + 1 位字母”。同文去重后，在置信度最高的前 5 条中，优先取同字母后缀的最长连续编号组（至少两条）；等长时取组内最低置信度更高的一组。没有连续组时取置信度最高的前 3 条。
- 任一类别缺少可靠文字，或正常 STOP 时没有有效频率，结果仍入库并标为待复核。OCR 待复核保存全部原始帧；仅缺频率时保留 OCR 选定证据。

历史和图片管理支持按文字包含／整行精确、完整行位数、机器、本地日期和复核状态查询。查询词同样去空白并转大写，`%`、`_` 按普通字符处理；不推算未保存的编号。人工修改逐行标准化后优先用于查询，原 OCR 文字和复核原因保留；仅确认原结果时不写人工文字。

### 保存与失败

每机保持一个现场活动周期和多个后台周期。`machine.max_inflight_cycles` 默认 2，要求正整数，统计所有未完整回收的周期；满载显示“后台处理积压，本次启动未采集，请暂停换带”并记录异常，拒收本次 START，不淘汰旧轮也不补拍，需等本次物理 CLOSE 后再受理后续 START。软件不会暂停实体机器。业务库保存机器与测量记录，独立运行库保存异常事件。证据路径为 `{evidence_directory}/YYYYMMDD/机器编号/周期编号/`，日期取测量开始时的本地日期；历史按保存的证据路径读取。

无采集帧、OCR 执行错误或超时、周期中断不生成测量记录，转入异常处理；普通失败只处理所属周期，现场关闭并安全停流后仍可受理下一轮，失败轮的线程和审计继续占用容量直到真正回收。迟到的旧周期结果不能混入新周期。明确的单台相机设备故障使该机不可用，其他机器继续运行；图片写入、数据库提交、异常审计失败和未知系统异常会停止监测。设备修复后需重新启动客户端。

## 安装、配置与启动

现场相机链路目前使用 **Windows 海康 MVS SDK**。准备 Python 3.10 和 [uv](https://docs.astral.sh/uv/)，从仓库根目录安装锁定依赖：

```powershell
uv sync --frozen
```

另按 [PaddlePaddle 官方安装说明](https://www.paddlepaddle.org.cn/documentation/docs/zh/install/index_cn.html)，将匹配本机 CPU/GPU 的 PaddlePaddle 运行时安装到项目 `.venv`；它未包含在项目依赖中。`src/ocr/config.yaml` 当前使用 `gpu:0`，需核对设备、模型、ROI 和预处理配置。桌面实际加载的是这份文件。

启动前核对 `config/config.yaml`：

- 业务库、运行库、证据目录与 MVS SDK 路径；文件内相对路径以 `config/` 为基准。
- 相机曝光、增益和频闪线路／信号源；串口、Modbus 参数和机器到 DI 的映射。仓库值不是现场通用值，启用机器须绑定互不重复的非负整数通道。

```powershell
uv run --no-sync python -m ui
```

桌面入口会初始化配置指向的数据库表。在“机器管理”添加并启用机器、填写相机和频率仪编号，再到“系统配置”核对 DI 绑定，最后点击“启动监测”。机器与配置修改须等待监测完全停止；配置保存后下次启动监测生效。`--no-sync` 避免启动时重同步环境；重新同步依赖时需留意单独安装的 PaddlePaddle。

## 当前边界与运维

- OCR 已接入；图像初筛仍原样通过全部帧，尚无有效的质量筛选。共享引擎仍串行使用，当前等锁 10000ms、处理 3000ms；并行接收周期不代表这些期限已适合 CPU 吞吐，需现场测量调整。
- 默认周期容量 2 是保守起始值，内存和持续换带负荷尚需真机验证，不能承诺无限连续运行不漏采。新轮取流与旧轮 JPG 编码并行的 MVS SDK 兼容性也待真机验证。停止监测等待全部采集、识别线程、保存和审计结束后才关闭 SDK 与数据库，退出期限不能强杀 Python 工作线程。
- **真实频率仪协议尚未接入**，当前每轮按间隔生成最多 3 条模拟读数，不能作为现场实测频率。
- 图片数量只反映现存文件，不能证明证据完整；历史详情仅预览前 4 张，完整证据可在图片管理或记录目录查看。
- 备份、校验、独立恢复、测试和模拟步骤见 [运维与验证](docs/operations.md)。模拟脚本使用真实 OCR，并写入配置中的真实业务库和证据目录，运行前必须确认数据去向。
