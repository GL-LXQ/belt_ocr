## Agent 规则

### 不确定性确认规则

- 编码时遇到需求、业务规则、接口契约、数据结构、兼容性或实现方案不明确时，必须先向用户确认，不得自行猜测。

### 代码修改规则

- 禁止过度防御性编程：信任内部流程已保证的数据约束，不重复校验；仅在外部输入、明确的异常边界或实际并发风险处保留必要检查。
- 首先保证代码的可读性，代码可读性大于代码优雅性。
- 所有变量和函数名必须使用有意义的英文单词或者英文缩写，以动词（函数）或名词（变量）开头，严格避免单字母、拼音或自造缩写，让人无需上下文就能一眼看懂它的作用。
- 用pytest校验所写代码，减少不必要的校验。

### 注释和文档编写规则

- 所有注释使用中文，注释要贴近代码逻辑,并且写的易懂。
- 尽可能的为每段代码写上注释。
- 注释只说明“这段代码做什么”，不解释原因、原理和背景。
- 注释按完整的小步骤划分，紧贴对应代码；连续出现数据准备、统计、执行、结果整理等不同操作时分别注释，避免一句概括整段，也不逐行重复代码。
- 连续 3～5 行代码如果包含独立处理逻辑，应在代码块前添加注释。
- 涉及固定英文标识、接口字段名、配置键名或第三方规范时，可以保留英文。
- 代码生成完成后，检查是否存在多个不同操作连续出现但没有注释；如有，必须补充。
- 仅当项目目的、主流程、对外行为、运行方式或重要限制变化时，更新 `README.md` 中对应的现有段落；不得追加逐次变更记录，纯样式调整或内部重构无需修改 README。
- 函数的注释必须包含：一句话总结该函数作用、完整Args注释、 完整Return，函数注释中的 Returns 必须提供完整返回数据示例，并为每个字段添加简明中文说明。
- Returns 示例中每个字段（含嵌套字段）独占一行，中文说明以行内注释写在该字段同一行。

### 封装和拆分规则

- 不要为了形式整洁而进行抽象封装。如果一个函数中的内容只有10行代码，不要封装这个函数。
- 只有出现复用、复杂度明显升高、函数过长、职责边界明确，才允许拆分函数。

### 接口返回规则

- 必须设置一个主流程函数，在其中串联完整业务逻辑，形成清晰的执行闭环。主流程函数应优先使用与业务相关的名称。
- 主流程函数负责按顺序组织初始化、数据获取、处理、结果输出和资源释放。
- 一次性使用、逻辑简单的小功能直接写在主流程中，不单独拆分函数。
- 拆分后的函数必须承担完整、明确的子任务，不得只包装一两行普通代码。
- 只有多个接口共用统一响应格式，或项目已有固定响应封装时，才允许抽取响应构造逻辑。

### Python 换行规则

- Python 每行不超过 120 个字符。
- 函数定义和调用的完整语句不超过 120 字符时保持单行；超过时每行一个参数，嵌套调用独立按同样规则判断。
- 字典字段和 return 中的多个返回元素一律每行一个。
- 除上述情况外，未超过 120 个字符的完整语句保持单行，仅在超过行宽或结构明显复杂时换行。
